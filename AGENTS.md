# AGENTS.md

## Project Summary

This repository contains a learning-focused Task Tracker application with a FastAPI backend and a vanilla HTML/CSS/JavaScript frontend.

The API supports creating, retrieving, listing, partially updating, and deleting tasks. Tasks can have a status, priority, assignee, optional due date, and tags. Storage is an in-memory Python dictionary, so all task data is lost when the backend process restarts.

Primary implementation references:

- `app/main.py` — FastAPI application and task endpoints.
- `app/models.py` — Pydantic request and response models.
- `app/storage.py` — in-memory task storage, filtering, and overdue logic.
- `app/business_rules.py` — permitted task-status transitions.
- `frontend/index.html` — browser UI.
- `tests/` — API and model behavior tests.
- `docs/` — decisions, user stories, verification notes, and course documentation.

## Supported Setup and Run Commands

Run commands from the repository root unless a command changes directories.

Create and activate a virtual environment on Windows PowerShell:

```powershell
python -m venv venv
.\venv\Scripts\Activate.ps1
```

Install application and test dependencies:

```powershell
pip install -r requirements.txt
pip install pytest httpx
```

Create local environment configuration:

```powershell
Copy-Item .env.example .env
```

Run the backend:

```powershell
uvicorn app.main:app --reload --port 8001
```

The API documentation is then expected at `http://127.0.0.1:8001/docs`.

Serve the frontend:

```powershell
cd frontend
python -m http.server 5500
```

Run the test suite from the repository root:

```powershell
pytest -v
```

The repository documentation reports an expected result of 21 passing tests. Treat that as a documented expectation, not a current test result, unless the suite has been run in the current working tree.

Build and run the Docker image:

```powershell
docker build -t task-tracker:dev .
docker run --rm -d -p 8001:8000 --name tt-dev task-tracker:dev
```

## API and Business Rules

### Task fields and defaults

A created task has these fields:

- `id`: generated by the in-memory storage layer.
- `title`: required string.
- `description`: optional; defaults to an empty string.
- `status`: defaults to `ToDo`.
- `priority`: defaults to `Medium`.
- `assignee`: optional; defaults to `null`.
- `due_date`: optional date.
- `tags`: defaults to an empty list.
- `created_at` and `updated_at`: generated as UTC timestamps.

Request models reject unknown fields.

### Title validation

- A title is required when creating a task.
- It must be a string.
- Leading and trailing whitespace is removed.
- It cannot be blank after trimming.
- It cannot exceed 200 characters.
- A task update may omit the title, but a supplied title follows the same rules.

### Statuses and transitions

The confirmed statuses are:

- `ToDo`
- `InProgress`
- `Done`

The only permitted status transitions are:

- `ToDo` → `InProgress`
- `InProgress` → `Done`
- `Done` → `InProgress`

All other transitions return HTTP 422, including assigning the task its current status.

### Priorities

The confirmed priorities are:

- `Low`
- `Medium`
- `High`

Other priority values are rejected.

### Due dates and overdue tasks

- A due date is optional.
- A task is overdue only when its due date is earlier than the current local date and its status is not `Done`.
- A task due today is not overdue.
- Tasks without due dates are not overdue.
- The list endpoint can combine overdue, status, and priority filters.

### Tags

- Tags must be supplied as a list of strings.
- Leading and trailing whitespace is removed from each tag.
- Empty tags are discarded.
- Duplicate tags are removed case-insensitively.
- The casing and order of the first occurrence are preserved.
- Tags can be cleared by updating them to an empty list.
- No maximum tag count, tag length limit, or tag character restriction is confirmed.

### Storage and API behavior

- Tasks are stored only in memory and disappear when the backend restarts.
- IDs are decimal strings generated from the current dictionary size plus one.
- List results are sorted by creation time in ascending order.
- A partial update preserves fields that were not supplied.
- An empty partial update returns the existing task unchanged.
- Missing task IDs return HTTP 404 for retrieve, update, and delete operations.
- Successful deletion returns HTTP 204 with no response body.
- No authentication or authorization behavior is confirmed.
